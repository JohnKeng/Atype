1. 整體架構兩台裝置、一條對外的線

兩端都在裝置內完成錄音與辨識，唯一離開裝置的是「已經轉成繁體的文字」，送到你自己申請 key 的 LLM 服務整理。沒有自家伺服器；詞典與 prompt 用 iCloud Drive 同步。

2. 共用管線兩端相同的七個階段

Mac 與 iPhone 跑的是同一條管線，差別只在「熱鍵」與「貼上」兩端的平台 API。繁體與排版由確定性規則保證，LLM 只負責需要語意判斷的事（贅詞、自我更正、分段），而且逾時就跳過。

3. Mac 流程Handy 已經做好的部分 vs 你要接的部分

Handy 負責熱鍵、錄音、HUD、可靠貼上與歷史；你只需要選模型、填 LLM key、貼 prompt。之後 fork 時要改的四處是：Apple SpeechTranscriber 引擎、Claude Messages API、OpenCC 後置與 pangu、拼音詞典。

4. iPhone 流程為什麼主入口是 Action Button，不是鍵盤

Apple 的硬限制：iOS 鍵盤 extension 不能存取麥克風（開 Full Access 也不行），記憶體上限約 30–60 MB。所以錄音與辨識一定在主 App，鍵盤最多只能「插字」。自用最省事的做法是完全不經鍵盤：Action Button 錄音 → 文字進剪貼簿 → 長按貼上。

5. 模型分層本地優先，雲端只做整理

自用時成本不是問題，選的是品質與「音訊不出裝置」。辨識全部本地；整理用雲端 LLM，兩家都申請 key，用 50 句自己的測試句比一週再定。

6. 第 0 天：不寫程式先用起來Mac 約 30 分鐘

  1. 裝 Handy，授權麥克風與輔助使用brew install --cask handy 或從 GitHub 下載。重 build 或改簽章後輔助使用授權會「看似有效實則失效」，這是 Handy 已知行為，重新加入即可。
  2. 模型選 SenseVoice-Small在 Handy 的模型清單下載。不要選 Parakeet（沒有中文）或 Whisper turbo（簡繁混出、幻覺多）。
  3. 熱鍵設 Fn 按住若「系統設定 → 鍵盤 → 按下 🌐 鍵時」是「開始聽寫」，改成「不執行任何操作」，否則系統會先攔走 Fn。外接非 Apple 鍵盤沒有 Fn 事件，改 Right Option。
  4. 後處理接自己的 LLM keyGemini 用 OpenAI 相容端點 https://generativelanguage.googleapis.com/v1beta/openai/、model gemini-3.1-flash-lite；Claude 若 Handy 現版無法直接接，就等第 3 週 fork 時接 Messages API。
  5. 貼 zh-TW prompt、繁簡轉換選繁體、填詞典prompt 在 docs/PLAN.md §4.2：「你是文字濾鏡，不是助理」開頭，含繁體、中英空格、自我更正、注入防護規則與範例。
  6. iPhone 先用捷徑頂著「聽寫文字」→ POST 到 LLM API → 拷貝到剪貼簿，綁 Action Button。第 2 週再換成自己的 App。

7. 四週計畫一個人、業餘時間

不做的事：後端、帳號、收費、上架與審查、Windows / Android、串流逐字寫進目標 App、iOS 自動跳回原 App 或任何私有 API、自己訓練辨識模型。
